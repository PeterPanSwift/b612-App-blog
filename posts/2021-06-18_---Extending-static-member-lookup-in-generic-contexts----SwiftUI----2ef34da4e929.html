利用 Extending static member lookup in generic contexts 簡化 SwiftUI 程式

Swift 5.5 之後，我們在撰寫 SwiftUI 程式時有了更方便的寫法。

比方我們看看以下例子，原本設定 TextField 圓角的程式如下，須傳入 RoundedBorderTextFieldStyle。

struct ContentView: View {
    @State private var name = ""
    
    var body: some View {
        TextField("name", text: $name)
            .textFieldStyle(RoundedBorderTextFieldStyle())
     }
}

現在我們只要輸入 . ，然後再從自動完成選單裡選擇 roundedBorder。

struct ContentView: View {
    @State private var name = ""
    
    var body: some View {
        TextField("name", text: $name)
            .textFieldStyle(.roundedBorder)
     }
}

類似的例子還有很多，比方以下例子。

  • 傳入 .grouped 設定 list style，不用像以前一樣傳入 GroupedListStyle()。
struct ContentView: View {
    
    var body: some View {
        List {
            Text("🐺")
            Text("🐗")
            Text("🐴")
            Text("🦄")
        }
        .font(.system(size: 100))
        .listStyle(.grouped)
    }
}
  • 傳入 .yellow，不用像以前一樣傳入 Color.yellow。
struct ContentView: View {
    
    var body: some View {
        Text("🦸‍♂️ 🦹‍♀️")
            .background(.yellow)
    }
}

為什麼 Swift 5.5 能做這樣的簡化呢 ? 跟 SE-0299 的 Extending Static Member Lookup in Generic Contexts 有關。

Using static member declarations to provide semantic names for commonly used values which can then be accessed via…github.com

讓我們用以下 protocol Idol 的例子說明。

protocol Idol {
    func sing()
}
struct Man: Idol {
    let name: String
    func sing() {
    }
}
extension Idol where Self == Man {
    static var bestMan: Self { Man(name: "Peter") }
}
func showIdol(_ idol: Man) {
    print(idol)
}
showIdol(.bestMan)

我們在 extension Idol 裡宣告 type property bestMan，因此在呼叫 showIdol 時我們可以方便地傳入 .bestMan，省略型別 Man。

Swift type property，type method ＆ enum 的型別省略
使用 Swift 的 type property，type method ＆ enum 時，型別省略可以讓我們的手指輕鬆不少，少打一些字。medium.com

然後當 function showIdol 是 generic function 時 將產生紅色誤誤，顯示 Cannot infer contextual base in reference to member ‘bestMan’。

此時我們無法省略型別，必須輸入完整的 Man.bestMan。

showIdol(Man.bestMan)

而 Swift 5.5 的 Extending Static Member Lookup in Generic Contexts幫我們改進了這個問題，即使 function 是 generic function，它也能聰明地找到 Man 下的 property best Man，因此我們可以傳入 .bestMan，省略型別 Man。

func showIdol<T: Idol>(_ idol: T) {
    print(idol)
}
showIdol(.bestMan)

現在我們再回過頭看看剛剛 SwiftUI 的例子，

struct ContentView: View {
    @State private var name = ""
    
    var body: some View {
        TextField("name", text: $name)
            .textFieldStyle(.roundedBorder)
    }
}

function textFieldStyle 的宣告如下，它是一個 generic function，要求型別 S 遵從 protocol TextFieldStyle。

func textFieldStyle<S>(_ style: S) -> some View where S : TextFieldStyle

roundedBorder 的宣告如下，它是 TextFieldStyle 下宣告的 type property。

extension TextFieldStyle where Self == RoundedBorderTextFieldStyle {
    public static var roundedBorder: RoundedBorderTextFieldStyle { get }
}

整個寫法就像我們剛剛的 Idol & Man 例子，因此可以套用 Swift 5.5 的Extending static member lookup in generic contexts，我們設定 text filed style 時只要傳入 .roundedBorder。
