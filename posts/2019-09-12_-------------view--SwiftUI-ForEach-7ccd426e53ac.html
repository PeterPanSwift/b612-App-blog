將集合裡的資料變成一個個 view 的SwiftUI ForEach

SwiftUI 提供 ForEach 型別幫助我們將集合裡的東西合併成一個 view，大大簡化我們需要自己輸入的程式，也解決了 ViewBuilder 參數裡的元件數量問題，接下來就讓我們以劉增瞳的你從不知道歌詞為例說明吧。

將集合裡的資料變成一個個 view 的SwiftUI ForEach

SwiftUI 提供 ForEach 型別幫我們將集合裡的東西生成一個個 view，然後再合併成一個 view，大大簡化我們要自己輸入的程式，接下來我們以可愛的動物為例說明 ForEach 主要的三種寫法。

  • ForEach 搭配 Range。
  • ForEach 搭配 id。
  • ForEach 搭配 Identifiable。
ForEach | Apple Developer Documentation
A structure that computes views on demand from an underlying collection of identified data.developer.apple.com

呈現 array 內容

首先我們先看看沒有 ForEach 時如何在畫面上呈現 array 內容。

以下程式的 animals 有三個動物，因此我們以 Text(animals[0])、Text(animals[1])、Text(animals[2]) 顯示。這樣的寫法在 array 成員數量不多時還可行，但數量很多時，豈不是要寫到天荒地老 ?

struct ContentView: View {
    let animals = ["🦊", "🐨", "🐧"]
    
    var body: some View {
        VStack {
            Text(animals[0])
            Text(animals[1])
            Text(animals[2])
        }
        .font(.largeTitle)
    }
}

因此接下來我們將請 ForEach 出馬，透過它就算 array 成員有一百個也可以幾行程式就搞定。

開始前先將 VStack { } 的內容清空。

struct ContentView: View {
    let animals = ["🦊", "🐨", "🐧"]

    var body: some View {
        VStack {
           
        }
        .font(.largeTitle)
    }
}

ForEach 搭配 Range

在 VStack { } 裡輸入 fore，選擇 ForEach(_ data: Range<Int>, content: (Int) -> View)。

以上的 ForEach 搭配的 init 如下。

init(_ data: Range<Int>, @ViewBuilder content: @escaping (Int) -> Content)
init(_:content:) | Apple Developer Documentation
Creates an instance that computes views on demand over a given constant range.developer.apple.com

參數說明

  • data

型別 Range 的 data 控制元件的數量， 比方 0..<3 將產生 3 個參數 content 回傳的元件。

值得注意的，data 的型別是 Range，因此只能用 ..<，不能使用 ClosedRange 的 … 語法。

  • content

回傳產生的元件。在 (Int) -> View 的框框按下 Return 鍵後將自動輸入下圖的 closure { } 程式。

在參數 Int 的框框輸入自訂的名字，比方 index，然後在 code 的框框輸入回傳的元件 Text(animals[index])。

ForEach(0..<3) { index in
    Text(animals[index])
}

ForEach 將 array 的內容變成一個個 view，ForEach(0 ..< 3) 會產生 3 個 { } 裡的 view，分別用 index 為 0、1、2 產生 Text(animals[0])、Text(animals[1])、Text(animals[2])。

完整程式如下。

struct ContentView: View {
    let animals = ["🦊", "🐨", "🐧"]

    var body: some View {
        VStack {
            ForEach(0..<3) { index in
                Text(animals[index])
            }
        }
        .font(.largeTitle)
    }
}

剛剛的寫法有個缺點， 每當 array 的成員數量改變時要調整 ..< 的範圍，更好的寫法是將 0 ..< 3 改成 0..<animals.count，自動依據 array 的成員數量生成 view。

struct ContentView: View {
    let animals = ["🦊", "🐨", "🐧"]

    var body: some View {
        VStack {
            ForEach(0..<animals.count) { index in
                Text(animals[index])
            }
        }
        .font(.largeTitle)
    }
}

雖然結果是對的，不過 Xcode 卻會顯示以下的警告訊息。

Non-constant range: argument must be an integer literal

這是因為 ForEach 搭配參數 Range 時，它要求 Range 必須是固定的，否則可能會產生資料錯亂的問題。等下我們將介紹 ForEach 搭配 id 的寫法消除此警告。

ps: 當 array 的數量會變動時，使用 ForEach 搭配參數 Range 會出問題。相關說明可參考以下連結。

ForEach(_:content:) should only be used for constant data
利用 SwiftUI 的 ForEach，我們可以快速產生多個 UI 元件，不過當 ForEach 搭配 range 型別的參數時，它的數量只能是固定的，否則會產生錯誤，例如以下例子:medium.com

ForEach 搭配 array 的 indices

剛剛的程式還可以更簡化， 我們不須手動輸入0..<animals.count，讀取 array 的 indices 即可取得它的數字範圍。

ForEach(animals.indices) { index in
    Text(animals[index])
}

此寫法一樣會有黃色警告，等下我們將介紹搭配 id 的寫法消除此警告。

ForEach 搭配 id 呈現 array 的內容

當我們想呈現的內容來自 array 時，也可以將 array 當參數傳入 ForEach。

首先將 VStack { } 的內容清空。

VStack {
    
}

在 VStack { } 裡輸入 forid，選擇 ForEach(_ data:, id:, content: (RandomAccessCollection.Element) -> View)。

參數 data 的型別是 RandomAccessCeollection，因此可傳入 array animals。此寫法需要額外設定型別 KeyPath 的參數 id，id 將設定 array 成員的 id，到時候 ForEach 將利用 id 區分 array 裡的成員。在此我們傳入 \.self，表示 array 成員自己就是 id，因此 🦊 的 id 是 🦊，🐨 的 id 是 🐨，🐧 的 id 是 🐧。

struct ContentView: View {
    let animals = ["🦊", "🐨", "🐧"]

    var body: some View {
        VStack {
            ForEach(animals, id: \.self) { animal in
                Text(animal)
            }
        }
        .font(.largeTitle)
    }
}

\.self 的寫法跟 Swift KeyPath 有關，有興趣的朋友可進一步查詢相關說明。

Swift 方便存取 property 的 KeyPath & KeyPath as Functions
Swift 的 KeyPath 可以指定某個 property 或 subscript，方便我們存取資料的 property 或 subscript，接下來就讓我們以 Song 為例，看看它特別的地方吧。medium.com

不過並非任何東西都可以當 id，依據 ForEach 的定義，id 的型別必須遵從 protocol Hashable，比方我們熟悉的 Int & String 資料都可以當 id，因為它們有遵從 protocol Hashable。

struct ForEach<Data, ID, Content> where Data : RandomAccessCollection, ID : Hashable
Swift 的 Hashable protocol
Swift 裡有一個特別的 Hashable protocol，我們在很多地方都可以看到它的蹤跡。medium.com

ForEach 搭配成員是自訂型別的 array

當 array 的成員是比較複雜的型別時，我們可以用 KeyPath 指定以成員的某個 property 當 id，例如以下例子的 \.emoji 表示以 Animal 的 emoji 當 id。

struct Animal {
    let name: String
    let emoji: String
    let weight: Int
}

struct ContentView: View {
    let animals = [
        Animal(name: "Fox", emoji: "🦊", weight: 14),
        Animal(name: "Koala", emoji: "🐨", weight: 9),
        Animal(name: "Penguin", emoji: "🐧", weight: 14)
    ]
    
    var body: some View {
        VStack {
            ForEach(animals, id: \.emoji) { animal in
                HStack {
                    Text(animal.emoji)
                    Text(animal.name)
                    Spacer()
                    Text("\(animal.weight)kg")
                }
            }
        }
        .font(.largeTitle)
        .padding()
    }
}


若我們改用 \.weight，以體重當 id，將會產生特別的問題。

ForEach(animals, id: \.weight) { animal in
    HStack {
        Text(animal.emoji)
        Text(animal.name)
        Spacer()
        Text("\(animal.weight)kg")
    }
}

Fox & Penguin 的 weight 都是 14，造成 array 裡有重覆的 id，因此畫面上變成顯示兩個 Fox。

利用 id 消除警告 Non-constant range: argument must be an integer literal

當 ForEach 搭配 Range，參數 id 傳入 \.self，使用 index 當 id 則可消除之前看到的警告 Non-constant range: argument must be an integer literal。

struct ContentView: View {
    let animals = ["🦊", "🐨", "🐧"]
    
    var body: some View {
        VStack {
            ForEach(animals.indices, id: \.self) { index in
                Text(animals[index])
            }
        }
        .font(.largeTitle)
    }
}

ps: 若是搭配動畫，使用 array 的 index 當 ForEach 的 id 可能會有特別的問題。

使用 array 的 index 當 ForEach id 的特別問題
當我們用 SwiftUI 的 ForEach 顯示 array 的內容時，通常需要指定區分成員的 id。medium.com

ForEach 搭配 Identifiable 呈現 array 的內容

剛剛產生 ForEach 時，型別 KeyPath 的參數 id 是為了區分 array 成員。不過當成員的型別遵從 protocol Identifiable ，它本身就會宣告用來區分的 property id，因此 ForEach 搭配 Identifiable 的資料時將可省略參數 id。

Identifiable | Apple Developer Documentation
A class of types whose instances hold the value of an entity with stable identity.developer.apple.com

以剛剛的 Animal 為例，我們讓它遵從 protocol Identifiable，在其中宣告 property id。id 的型別必須遵從 Hashable protocol，因此最簡單的莫過於用整數或字串當 id，比方用 Animal 的 emoji 當 id。

struct Animal: Identifiable {
    var id: String { emoji }
    let name: String
    let emoji: String
    let weight: Int
}

不過 id 要確保不會重覆，而 Animal 的 emoji 有可能重覆，因此更常見的方法是利用 UUID 當 id，因為它可以幫我們產生獨一無二，不會跟別人同名的 ID。

import Foundation

struct Animal: Identifiable {
    let id = UUID()
    let name: String
    let emoji: String
    let weight: Int
}
iOS App 如何產生獨一無二的 ID
開發 iOS App 時，有時我們需要產生獨一無二，不會跟別人同名的 ID。比方我們做了一個拍照 App，為了讓照片的檔名不會重覆，我們可用以下方法產生獨一無二的 ID。medium.com

此時 ForEach 時將可省略參數 id，因為 Animal 的 id 就可以區分了。

struct ContentView: View {
    let animals = [
        Animal(name: "Fox", emoji: "🦊", weight: 14),
        Animal(name: "Koala", emoji: "🐨", weight: 9),
        Animal(name: "Penguin", emoji: "🐧", weight: 14)
    ]
    
    var body: some View {
        VStack {
            ForEach(animals) { animal in
                HStack {
                    Text(animal.emoji)
                    Text(animal.name)
                    Spacer()
                    Text("\(animal.weight)kg")
                }
            }
        }
        .font(.largeTitle)
        .padding()
    }
}

ForEach 搭配的 init 宣告如下。

extension ForEach where ID == Data.Element.ID, Content : View, Data.Element : Identifiable {
    public init(_ data: Data, @ViewBuilder content: @escaping (Data.Element) -> Content)
}
init(_:content:) | Apple Developer Documentation
Creates an instance that uniquely identifies and creates views across updates based on the identity of the underlying…developer.apple.com

只有當 array 成員遵從 Identifiable 才可省略 id，若沒有遵從 Identifiable，將出現錯誤 Referencing initializer ‘init(_:content:)’ on ‘ForEach’ requires that ‘Animal’ conform to ‘Identifiable’。

當 class 遵從 protocol Identifiable

遵從 protocol Identifiable 的 class 將自動得到識別的 id，不需另外宣告 id。

class Animal: Identifiable {
    let name: String
    let emoji: String
    let weight: Int
    
    init(name: String, emoji: String, weight: Int) {
        self.name = name
        self.emoji = emoji
        self.weight = weight
    }
}

若是搭配 SwiftData 的 @Model 定義的 class 型別，則會自動遵從 Identifiable。

import SwiftData

@Model
class Animal {
    var name: String
    var emoji: String
    var weight: Int
    
    init(name: String, emoji: String, weight: Int) {
        self.name = name
        self.emoji = emoji
        self.weight = weight
    }
}

讓 String & Int 遵從 protocol Identifiable

當 array 的內容是簡單的字串或數字時，我們也可以搭配 Identifiable，比方以下例子。

利用 extension 擴充 String，讓它遵從 protocol Identifiable，定義它的 id 是自己本身的字串內容。

extension String: @retroactive Identifiable {
    public var id: String { self }
}

ps: @retroactive 的目的是消除警告，原本程式會擔心未來 Swift 的 String 遵從 Identifiable，跟我們自己寫的遵從 Identifiable 衝突。

String 遵從 protocol Identifiable，所以現在 ForEach 傳入字串 array 時不用再傳入參數 id 。

struct ContentView: View {
    let animals = ["🦊", "🐨", "🐧"]
    
    var body: some View {
        VStack {
            ForEach(animals) { animal in
                Text(animal)
            }
        }
        .font(.largeTitle)
    }
}
