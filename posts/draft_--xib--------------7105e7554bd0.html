將 xib 的元件加入畫面的三種寫法

開發 UIKit iOS App 時，我們常利用 xib 設計可重覆利用的畫面元件，然後在 view controller 裡加入元件。




class ViewController: UIViewController {

    override func viewDidLoad() {
        super.viewDidLoad()
        
        if let loadingView = Bundle.main.loadNibNamed("LoadingView", owner: nil)?.first as? UIView {
            loadingView.translatesAutoresizingMaskIntoConstraints = false
            view.addSubview(loadingView)
            loadingView.widthAnchor.constraint(equalToConstant: 100).isActive = true
            loadingView.widthAnchor.constraint(equalTo: loadingView.heightAnchor).isActive = true
            loadingView.centerXAnchor.constraint(equalTo: view.centerXAnchor).isActive = true
            loadingView.centerYAnchor.constraint(equalTo: view.centerYAnchor).isActive = true
        }
    }
}


class ViewController: UIViewController {

    override func viewDidLoad() {
        super.viewDidLoad()
        
        let nib = UINib(nibName: "LoadingView", bundle: nil)
        if let loadingView = nib.instantiate(withOwner: nil).first as? UIView {
            loadingView.translatesAutoresizingMaskIntoConstraints = false
            view.addSubview(loadingView)
            loadingView.widthAnchor.constraint(equalToConstant: 100).isActive = true
            loadingView.widthAnchor.constraint(equalTo: loadingView.heightAnchor).isActive = true
            loadingView.centerXAnchor.constraint(equalTo: view.centerXAnchor).isActive = true
            loadingView.centerYAnchor.constraint(equalTo: view.centerYAnchor).isActive = true
        }
    }
}



class LoadingView: UIView {
    @IBOutlet weak var activityIndicatorView: UIActivityIndicatorView!
}



class ViewController: UIViewController {

    override func viewDidLoad() {
        super.viewDidLoad()
        // Do any additional setup after loading the view.
        
        let nib = UINib(nibName: "LoadingView", bundle: Bundle(for: LoadingView.self))
        if let loadingView = nib.instantiate(withOwner: nil).first as? LoadingView {
            loadingView.translatesAutoresizingMaskIntoConstraints = false
            loadingView.activityIndicatorView.startAnimating()
            view.addSubview(loadingView)
            loadingView.widthAnchor.constraint(equalToConstant: 100).isActive = true
            loadingView.widthAnchor.constraint(equalTo: loadingView.heightAnchor).isActive = true
            loadingView.centerXAnchor.constraint(equalTo: view.centerXAnchor).isActive = true
            loadingView.centerYAnchor.constraint(equalTo: view.centerYAnchor).isActive = true
        }
    }
}

## 🍰 簡單開發 → `bundle: nil`

### ✅ 優點：

* 寫法簡潔。
* `.xib` 在主 App 中就好用。
* 開發快、心情好、bug 少（理想狀況）。

### ❌ 缺點：

* 如果 `.xib` 跑去別的 module（像是 framework、Swift Package、CocoaPods）... 它就會迷路找不到啦！

---

## 🍮 模組化或複用 → `bundle: Bundle(for: ...)`

### ✅ 優點：

* 更安全、更準確地指定 `.xib` 的所在位置。
* 模組化開發時不會出錯（像是你把元件封裝成別的框架、Libary）。
* 對於 **大型 App、多人開發、元件化設計** 超好用！

### ❌ 缺點：

* 稍微長一點（但比起抓不到 nib，這根本不算缺點～）

---

## 🏁 結論（可愛撒嬌版）

🥺 如果你只是做一人小品 App，`.xib` 都乖乖在主工程裡～
👉 `bundle: nil` 就像走小路去買冰淇淋，快又輕鬆！

🤓 但如果你在寫一個準備要賣給全世界的超級框架，或你是團隊合作、寫元件給別人用～
👉 `bundle: Bundle(for: ...)` 就像帶著地圖去冒險，保證找得到寶藏✨

---

🔧 建議習慣使用 **`Bundle(for: ...)`**，因為：

> 就算你現在用不到，也能未雨綢繆，未來更不容易踩雷～🌧️☂️
